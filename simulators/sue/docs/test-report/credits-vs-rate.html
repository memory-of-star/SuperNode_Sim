CBFC 信用窗口(credit limit)对端口线速的影响

SUE 仿真平台 · sue-thpt-line-rate · 2 节点直连 · LLR+CBFC · creditSize=56B · 512B 帧 · clean(无误码)· 2026-08-14 THU 对齐预设(CF 阈值 2075B 即时退款,§12.37)

实测值(归一化后两种速率逐点完全重合 → 窗口字节语义、机制速率无关)
credit limit(信用/VC)400G 实测(Gbps)100G 实测(Gbps)占标称线速

场景:sue-thpt-line-rate(THPT_RATE=400Gbps/100Gbps,THPT_GBITS=10,clean 模式,每点一次全仿真,2026-08-14 实测)。
机制(THU 对齐预设:CBFC_CF_THRESHOLD_BYTES=Q=2075、CF_MIN=0,退款随数据量即时触发):帧 526B(512 载荷+14 头)= ceil(526/56)=10 信用,在途批次 k = ⌊CL/10⌋ 帧。 窗口 ≤ 504B(CL≤9)< 单帧 → 死锁(放不下任何帧);k×526 < Q(CL=10..39)→ 批次跨不过阈值,靠 CF_max 周期(100µs)兜底,逐帧节流(速率与时延无关); k×526 ≥ Q(CL=40 = ⌈2075/526⌉×10,离散量化)→ 批次内跨阈值 → 退款即时到达,跳变(93.5% 载荷效率天花板:512/546≈93.8%,差值=ACK/CtlOS 线占)。归一化后两速率逐点重合。
释放量子 Q 的影响(THPT_CF_THRESHOLD 扫描):跳变点 = ⌈Q/526⌉×10 credits——Q=2075→CL=40、Q=8192→CL=160、Q=16384→CL=320(三点实测 92.49/92.90/93.33 Gbps);Q 越大控制报文越省(频率=数据率/Q),但跳变窗口越大。
延迟释放与链路时延:退款 RTT 每加一个转发预算(300ns)或传播时延,线速区速率 = 线速 × W/(W+RTT×线速)(fwd=300ns 实测 CL=47:92.49→37.50 Gbps、CL=128 完全恢复);W=RTT×线速 时恰为半速。节流区与时延无关。
对比旧曲线(CF_MIN=125000B 每 10µs 退款,§12.36 实测,CS=256/2048B 帧):64/128/256/512 信用 → 11.5/22.9/45.9/91.8 Gbps@100G——退款节奏 60× 变快后窗口需求大幅下降(旧拐点 ~500 信用,新曲线 CL=40)。
