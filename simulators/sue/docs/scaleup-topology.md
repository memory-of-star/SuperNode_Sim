# ScaleUp 拓扑与规模场景(2026-08-13)

## 目标场景(对齐 DESIGN §1.1:512 卡 / 32 交换机 / 多平面)

- **8 卡机(machine)**:8 个 XPU + 1 颗**内置 switch 芯片**(SUESwitchNode)+ 2 个上行口。同机 8 XPU 经内部 switch 直通(1 跳);跨机流量经上行口出机。
- **超节点(supernode)**:N 台 8 卡机经 **2-plane fat spine** 互联。N=64(512 XPU,项目目标)/ 128(1024 XPU)/ 256(2048 XPU)。

## 拓扑结构(✅ 已实现)

```
machine i(0..N-1):                spine 层:
  XPU 8i+0..8i+7 ── 内部 switch ── uplink0 ── spine plane0(9N)
                            └─── uplink1 ── spine plane1(9N+1)
```
- 每 plane **1 台 fat spine**,上联**全部 N 台机器**(s8 双平面拓扑的直接放大)。跨机路径 = 机内 switch → spine → 对端机内 switch → XPU(4 跳),两平面**等代价 ECMP**。
- ⚠️ 设计教训(首版踩坑):"每 plane P 台 spine、机 i 只上联 spine[i/8]"的布局会把机器分组隔离——**跨组路径不存在**(spine 间无互连)。fat spine(或 spine-spine mesh)才能保证任意跨机路径;前者是本平台的基线选择。
- 节点数 = 9N+2;链路 = 10N(8 内部 + 2 上行)。

## 实测(冒烟:机内环 + 跨机点对点,clean、无损、双平面断言)

> **口径变更(2026-08-18,§12.46)**:smoke/stress conf 预设 `SUE_LINK_PROPAGATION_NS 100`(原默认 0)。动机:MTP 下 lookahead=0 致轮数暴雨(58 万轮)→ 7.5× 倒退;100ns 为铜/光传输量级物理合理值。代价:RTT +800ns/4 跳,sat 截面积 93.7%→90.85%(§12.39 W/(W+RTT·线速) 预测内)。历史 prop=0 数字见下表括注,`SCALE_PROP_NS=0`(stress)/手改 conf(smoke)可复现。

| 规模 | 帧/端点 | 单线程墙钟 | MTP 8 线程 | 结果 |
|---|---|---|---|---|
| 64 机 | 20 | 7.5s(prop=0 时 11.3s) | **4.3s(1.74×;prop=0 时 30.5s = 慢 2.7×)** | PASS(10240/10240 无损,双平面 1280/1280) |
| 128 机 | 5 | 21.2s(prop=0 时 27.8s) | **9.9s(2.14×;setup 1.0s)** | PASS |
| 256 机 | 2 | 98.7s(prop=0 时 111.5s) | **39.1s(2.53×;setup 7.9s)** | PASS |

观察:
- **setup 时间随规模超线性**:64 机 227ms / 128 机 1.39s / 256 机 7.87s(每翻倍 ×6 左右)——per-switch 全图 BFS × 每节点 std::map/std::set 开销。64 机(512 XPU 目标规模)可接受;**256+ 规模优化候选**:per-switch BFS 换扁平数组(节点号连续,std::map→vector)、或按机分组一次性 all-pairs(记录待办,本轮不做)。
- **run 时间主要由每引擎 ACK 周期定时器驱动**(640 引擎 × 41ns 周期 @2048B spacing → 83s;放宽到 16384B spacing → 11.3s)。512 卡满负载压测用 UEC 上限 spacing 16384B。
- **MTP 在低负载 64 机下慢于单线程**(LP 同步开销 > 并行收益)——符合预期;满负载下同结论(7.5× 慢,见下节)。

结论:
1. **织物饱和率 90.85% 截面积(prop=100 口径)**——缺口 = 控制帧/前导/IFG 开销 + RTT 信用窗代价(prop=0 时 93.7%:RTT 项为 800ns/4 跳 × 信用窗补偿,§12.39)。
2. **CBFC 信用窗在 1.68× 过载下全额吸收超额(零拒绝)**:128KB/VC 窗 + 2.5µs CF 节奏足以缓冲 86T→51.2T 的差额,注入侧无帧丢弃。
3. **MTP-8 满负载 3.33× 快于单线程**(3.64s vs 12.1s,prop=100 预设)——原 7.5× 倒退根因已定位并修复(§12.46:lookahead=0 轮数暴雨,58 万轮 × ~118µs/轮);轮数塌缩到 ~4k。聚合速率/投递/双平面分拆与单线程一致(credit_exhausted Δ21/263k 为重试边界决胜差,单线程复跑逐位稳定)。fork 级进一步优化候选见 §12.46。
4. **事件率主导项**:ACK 节奏 + CF_min/max 定时器(无负载 1.65M 事件/ms-sim;满负载 22.6M)。

## 建模决策

1. **复用 topo 文件入口**:生成器(`sue-scale-topo.{h,cc}` 模块代码)产出标准 topo 文件,走 `SetupSueNetwork` 既有解析/BFS+ECMP/设备创建路径——零新入口代码。
2. **MTP 分区**:自动分区每节点一 LP → 64 机 = 578 LP、256 机 = 2306 LP。64/128/256 机 MTP-8 全 PASS(prop=100 口径,1.74×/2.14×/2.53×;256 机 setup 7.9s 串行 BFS 占墙钟 ~20%,为大规模首要串行项)。
3. **流量模式**(冒烟):slot 0/7 跨机、slot 1–6 机内环。(ECMP 哈希熵已扩展为 SA/DA/FlowLabel FNV,§12.33——双平面由流哈希自然分拆,64 机实测 plane0/plane1 ≈ 1180/1380,不再依赖奇偶目的凑组;流量模式保留 slot 0/7 双组跨机以同时压两平面。)
4. **验证判据**:无损投递(送=收)、无 replay/discard、双 plane spine 均转发、墙钟/内存记录。
